## Теоретичні питання та пояснення

### Завдання 2. Гамма-корекція та формула перетворення

Для перетворення між sRGB та лінійним простором використано степеневу формулу з лекції 1 із показником $\gamma = 2.2$:
- Переведення у лінійну яскравість: $L = \left(\frac{V}{255}\right)^{2.2}$
- Переведення назад у sRGB: $V = \text{round}\left(255 \times L^{1 / 2.2}\right)$

#### Чому 128 — неправильна відповідь для суміші чорного й білого

Значення пікселів у sRGB (0–255) не є лінійними мірами фізичної кількості випромінюваного світла (фотонів). Вони закодовані нелінійно ($\gamma \approx 2.2$), щоб відповідати логарифмічній чутливості людського зору: людське око значно краще розрізняє градації темних відтінків, ніж світлих.

Фізичне змішування світла підкоряється лінійним законам оптики:
1. Переводимо чорний ($0$) та білий ($255$) у лінійну шкалу:
   $$L_1 = \left(\frac{0}{255}\right)^{2.2} = 0.0, \quad L_2 = \left(\frac{255}{255}\right)^{2.2} = 1.0$$
2. Усереднюємо фізичну інтенсивність світла ($50\%$ потужності):
   $$L_{\text{mid}} = \frac{0.0 + 1.0}{2} = 0.5$$
3. Переводимо назад у значення sRGB для дисплея:
   $$V = 255 \times (0.5)^{1 / 2.2} \approx 255 \times 0.72974 \approx 186$$

Якщо ж наївно взяти середнє арифметичне чисел $(0 + 255) / 2 \approx 128$, то фізична яскравість такого пікселя складе:
$$L = \left(\frac{128}{255}\right)^{2.2} \approx 0.218$$
Тобто лише **$\approx 21.8\%$** від яскравості білого замість потрібних $50\%$. Візуально такий колір виглядає брудним і надто темним. Правильна відповідь для змішування — **186**.

Аналогічно для усереднення чотирьох пікселів $0, 0, 0, 255$:
$$L_{\text{avg}} = \frac{0 + 0 + 0 + 1.0}{4} = 0.25 \implies V = 255 \times (0.25)^{1 / 2.2} \approx 136$$
Наївне середнє чисел дало б $63.75 \approx 64$, що відповідає лише $\approx 4.7\%$ фізичної яскравості.

### Завдання 4. Виведення початкового значення помилки Брезенхема $P = 2\Delta y - \Delta x$

Розглянемо перший октант: лінія йде з $(x_0, y_0)$ до $(x_1, y_1)$ праворуч і вниз, $0 \le \Delta y \le \Delta x$.

Рівняння прямої через дві точки:
$$y - y_0 = \frac{\Delta y}{\Delta x} (x - x_0) \iff F(x, y) = 2\Delta y(x - x_0) - 2\Delta x(y - y_0) = 0$$

На кожному кроці по осі $x$ ми безумовно робимо крок $x_{k+1} = x_k + 1$. Вибір для $y_{k+1}$ стоїть між двома сусідніми пікселями:
- $E = (x_k + 1, y_k)$ — рух строго на схід (прямо);
- $SE = (x_k + 1, y_k + 1)$ — рух на південний схід (по діагоналі).

Алгоритм середньої точки (Midpoint) оцінює положення прямої відносно середини між цими двома кандидатами — точки $M\left(x_k + 1, y_k + \frac{1}{2}\right)$:
$$d = \Delta y (x_k + 1 - x_0) - \Delta x \left(y_k + \frac{1}{2} - y_0\right)$$

Щоб позбутися дробу $\frac{1}{2}$ і залишитися в цілочисельній арифметиці, домножуємо критерій на 2:
$$P_k = 2d = 2\Delta y (x_k + 1 - x_0) - 2\Delta x (y_k - y_0) - \Delta x$$

Для початкового пікселя $(x_0, y_0)$ підставляємо $x_k = x_0$ та $y_k = y_0$:
$$P_0 = 2\Delta y (x_0 + 1 - x_0) - 2\Delta x (y_0 - y_0) - \Delta x$$
$$P_0 = 2\Delta y (1) - 0 - \Delta x = 2\Delta y - \Delta x$$

Знак величини $P_k$ вказує, з якого боку від ідеальної прямої лежить середина між пікселями:
- Якщо $P_k \le 0$: середина лежить вище прямої, отже, пряма ближча до пікселя $E$ ($y$ залишається без змін), а помилка на наступному кроці збільшується на $2\Delta y$.
- Якщо $P_k > 0$: середина лежить нижче прямої, пряма ближча до пікселя $SE$ ($y$ збільшується на 1), а помилка коригується на $2\Delta y - 2\Delta x$.

### Завдання 6. Результат порівняння з `cv2.line`

Під час тестування власної реалізації алгоритму Брезенхема та порівняння з бібліотечною `cv2.line` отримано такі результати:

1. **Лінія з лекції $(2, 2) \to (13, 5)$:**
   - Розійшлося пікселів: **0** (ідеальний збіг).
2. **Прямі відрізки та випадкові лінії:**
   - Діагональ $(0, 0) \to (99, 99)$: розбіжностей **0**.
   - Відрізок $(50, 50) \to (300, 150)$: розбіжностей **0**.
   - У тестовому наборі з 1000 випадкових відрізків у всіх напрямках розбіжностей не виявлено завдяки канонізації порядку точок $(x_0, y_0) \le (x_1, y_1)$ та точному цілочисельному правилу перемикання.

#### Чому взагалі можуть виникати розбіжності між алгоритмами малювання:
- **Правило розв'язання нічиїх (Tie-breaking rule):**  
  Коли математична пряма проходить рівно через середину між двома сусідніми пікселями ($P_k = 0$), різні реалізації можуть обирати крок або при $P \ge 0$, або при $P > 0$.
- **Субпіксельна арифметика:**  
  OpenCV всередині використовує алгоритм із фіксованою комою (зсув на 4 біти, тобто з точністю до $1/16$ пікселя), де координати центрів пікселів розглядаються як $(x + 0.5, y + 0.5)$. На деяких кутах нахилу це може зміщувати перемикання кроку по $y$ на один піксель раніше або пізніше.

## Використання ШІ

ШІ використовувався для консультацій щодо формул перетворення кольорів (sRGB $\leftrightarrow$ HSV), перевірки точності математичного виведення похибки Брезенхема та допомоги у складанні крайових випадків для тестів.
